# スマートフォンUI・グラフィック改善計画（v103〜）

依頼「WORLD DEFENSE — スマートフォンUI・グラフィック全面改善計画」に対する、調査結果と段階ごとの実装計画です。今回は**第1段階（UI整理）だけ**を実装しました。第2段階以降（グラフィック）は、試作品を確認してもらってから進めます。ゲームバランス・保存データは変更しません。

## 1. 現状の調査結果

| 項目 | 現状 |
| --- | --- |
| 配布形式 | 単一の `index.html`（約4.9MB）。`src/index.template.html` ＋ `src/*.js` を `node tools/build.mjs` で結合 |
| 画像 | `assets/`（約3.6MB）。`assets/manifest.json` のキーで参照し、ビルド時に base64 で埋め込む。画像がない場合は仮アイコンで描画 |
| 描画 | 1枚の `<canvas>`（論理 960×600、16:10）に毎フレーム全描画。背景は初回だけ別キャンバスに描いて再利用 |
| 兵士の絵 | 兵種ごとの基本画像7枚。歩行・攻撃・被弾・戦死のコマがあるのは騎兵・鉄砲兵・衛生兵の一部（計18枚）。上級職は基本兵種の絵＋色・印 |
| 敵・ボス | 敵は画像＋コマ。裏ボス（白虎・黄泉・富士・真・八岐大蛇）はコードで描く図形とコマ |
| 拡大 | canvas の `imageSmoothingEnabled` を設定しておらず、ドット絵を拡大するとぼやける |
| 画面（390px縦） | 戦場 374×234px。下にウェーブ操作・雇用・部隊8つ・塔4種・メニュー10個が縦に並び、ページの高さ1047px（スクロールが必要） |
| 画面（PC 1280×900） | 戦場 1064×665px。操作がその下に続き、ページの高さ1441px |
| 一時停止 | 「情報」画面だけ戦闘を止める。ほかの画面（ガチャ・図鑑など）は止めない |
| 試験 | Playwright の試験90本。多くが `#mapOpen` `#gacha` `[data-t]` などのボタンを直接押す |

**戦場の大きさの制約**：戦場は横長（16:10）で、縦画面では**画面の横幅が上限**になります。縦への引き伸ばしと横スクロール化は行わない方針なので、UIを整理しても戦場そのものの拡大は「画面の端まで使う」分（約4%）にとどまります。第1段階の主な効果は、**戦場と操作が1画面に収まり、スクロールせずに戦えること**です。さらに大きく見せる案は6章の「要相談」にまとめました。

## 2. 第1段階：UI整理（今回実装・v103）

- **コンパクト表示**（通常のURLの既定）
  - ウェーブ操作（開始・倍速・全回復・AUTO）の下に「⚔️ 部隊」「🏯 建設」「✨ 必殺技」「☰ メニュー」の4ボタンを1列に置く。押したものだけ画面の下から開く（同時に開くのは1つ）。
  - 中のボタンは従来の要素そのもの（IDと処理は同じ）で、場所だけを変えた。部隊8つの一覧・雇用・編成、塔4種の建設、強化・売却・武将配属・塔の育成・配置制限は従来どおり。
  - 部隊・塔を選ぶと引き出しは閉じ、従来の操作パネル（撤退・治療・強化・売却・必殺技）が出る。塔の種類を選ぶと引き出しを閉じ、そのまま草地をタップして建設できる。
- **必殺技**：塔・部隊に配属した武将を一覧にし、状態（使える／あと○秒／発動中／ウェーブ中に使えます）と「発動」ボタンを表示。処理は従来の必殺技ボタンと同じ。部隊・塔を選んで使う従来の操作も残す。
- **メニュー**：戦い（世界・編成・修練場）／武将・兵士の育成（ガチャ・主人公・育成情報）／装備・アイテム（装備倉庫・商店・秘伝錬成）／記録・その他（図鑑・途中保存・最初から・データ消去・表示の切り替え）にまとめた。
  - 新しく使えるようになった機能があれば、メニューのボタンに印を付ける。
- **戦場**：スマホでは画面の端から端まで表示（390px幅で 390×244px）。PC・横向きでは、戦場と操作の列が見えている高さに収まる大きさにする。
- **表示の切り替え**：メニューの「📱 表示」で従来の表示に戻せる（保存される）。
- **計測（390×844）**：ページの高さ 1047px → 844px（スクロールなし）。戦場・ウェーブ開始・4つのボタン・次の目標が1画面に収まる。
- **試験**
  - 確認用URL（`?debug`）は既存の試験が前提とする従来表示を既定にした。`?layout=compact` でコンパクトを確認する。
  - `?debug` を付けずに開く既存の試験9本は、`?layout=classic` を付けて従来表示で確認するように変更した。
  - 新規 `tools/test-compact-ui.mjs`（36項目）で、コンパクト表示の操作を確認する。

## 2.5 縦向きの戦場（試作・v104）

「要相談」の案2を、承認を受けて**試作**として実装しました。メニューの「🧪 戦場」で切り替えます（既定は横向きのまま）。

- 入口が上、城が下の縦長の戦場（600×960）。390px幅のスマホでは **390×624px**（横向きの 390×244px の約2.6倍の面積）で、操作の列まで1画面に収まる。
- **ゲームの座標と処理は変えない**（横960×縦600のまま）。描くときだけ入れ替える。
  - 地面・道・地形・弾：座標ごと入れ替えて描く（画面の x＝ゲームの y、画面の y＝ゲームの x）。
  - 兵士・塔・敵・城・裏ボス・体力の棒・札：位置だけ入れ替え、絵は立てたまま描く。
  - 文字・画像：入れ替えの途中でも立てて描く。
- タップ・ドラッグは画面の座標をゲームの座標へ戻してから処理するため、建設・配置・選択・移動の決まりは同じ。
- 切り替えはその場で反映され、設定として保存される（`worldDefense.ui.v1` の `layout: "vertical"`）。
- **試作として残っている見た目の課題**
  - 防衛戦の部隊は隊列が横向きのまま（攻城戦は兵士ごとに入れ替わる）。
  - 大砲・水攻めの弾の山なりが横へ膨らむ。
  - 裏ボスの演出の文字の一部が画面の左寄りに出る。
  - 道の名前の札の位置は仮。
- 試験：`tools/test-vertical-field.mjs`（18項目）で、実際のタップ・ドラッグによる建設・配置・選択・移動、防衛・攻城・真・八岐大蛇の描画、切り替えと保存、PC表示を確認。

## 3. 第2段階：グラフィック統一（試作品の確認後）

1. **ぼやけ対策（すぐ効く・低リスク）**：ドット絵の描画で `imageSmoothingEnabled = false` にし、整数倍に近い大きさで描く。
2. **試作品**：足軽・槍兵・弓兵・鉄砲兵・衛生兵・騎兵の6兵種を、同じ大きさ・同じドット密度・同じ光源で描き直した1枚の比較画像を作る。
   - 味方と敵は、旗印と配色で区別する。
   - 塔1種と城1つも同じ画風で作る。
   - 既存画像と並べて見てもらい、方向性が決まってから全体に広げる。
3. **素材の管理**：兵種×動作のコマを1枚のスプライトシートにまとめ、`manifest.json` で参照する（読み込み回数と容量を減らす）。1兵種あたり 待機2・歩行4・攻撃3・被弾1・戦死2 コマ程度を目安にする。
4. **上級職**：基本兵種のシートに、兜・武器・色の差分を重ねて描く方式を検討する（全職業を個別に描くと容量が大きくなる）。
5. **背景・城・塔**：明るい草原と道の色調を統一し、城に影と段差を付ける。装飾は戦場の視認性を優先して控えめにする。

> 画像はこの環境で描く必要があります。ドット絵の品質には限界があるため、まず少数を試作して確認してもらいます。参考作品の画像・キャラクターは使いません。

## 4. 第3段階：戦闘アニメーション

- 待機・歩行・近接攻撃・遠距離攻撃（弓・鉄砲）・騎兵の突撃・回復・被弾・戦死を、少ないコマとわずかな動き（上下の揺れ・前への踏み込み）の組み合わせで自然に見せる。
- 必殺技は、武将の顔のカットイン（既存）と範囲の光で強調する。通常攻撃は控えめにする。

## 5. 第4段階：イベントウィンドウ（戦闘を止めない）

- 既存の出来事（閃き・称号・節目・耐性・転職の解放・ネームド・復活の書・ボスの初回撃破）が起きたときに、画面中央の手前に大きなウィンドウを出す。
  - **戦闘は止めない**。背後の戦場が動いて見えるよう、ウィンドウは半透明にし、戦場の上部と城のHPが見えるようにする。
- 表示待ちの列（キュー）を作り、同時に1枚だけ表示する。短い間に同じ種類が続いたら「○人が閃いた」のようにまとめる。
- 通常のイベントは約3秒で自動で閉じ、タップですぐ閉じられる。重要なもの（ボスの初回撃破・最上級職・復活）は履歴に残す。
- 新しいスキルや報酬は追加しない（表示だけ）。

## 6. 第5段階：ボス演出・最適化と、要相談の案

- **ボス**：輪郭線・影・頭や攻撃する部位の強調、予兆の範囲表示、HPバーと状態異常の整理。判定・HP・能力・難易度は変えない。
- **負荷対策**：同時に出すエフェクトの上限、遠くのダメージ数字の間引き、「演出を控えめにする」設定（既存の `reduced` を拡張）。
- **要相談（戦場をさらに大きく）**
  1. **拡大表示**：戦場を約1.4倍に拡大し、指で左右にずらして見る（城と入口が同時には見えなくなる）。
  2. **縦向きの戦場**：入口を上・城を下にした縦長の戦場で描く。縦画面を最大限使えるが、描画の座標変換と配置ルールの見直しが必要な大きな変更。
